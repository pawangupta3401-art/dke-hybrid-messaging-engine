Cryptographic Specification and Implementation

End-to-end encryption with dynamic key evolution.

A peer-to-peer secure messaging engine combining ephemeral X25519 ECDH key agreement with per-message HKDF ratcheting and AES-256-GCM authenticated encryption. Every message advances the key chain.

Wire Architecture

Self-describing binary envelope.

The transport layer treats packets as byte streams. Each transmission packages an authenticated 30-byte header, variable ciphertext, and a 16-byte Poly1305 or GCM authentication tag.

Envelope Layout (TAD Section 4.1)
Total frame size equals 46 bytes plus the length of ciphertext payload.
MAGIC 4 Bytes
VERSION 1 Byte
FLAGS 1 Byte
SEQ 8 Bytes
NONCE 12 Bytes
CT_LEN 4 Bytes
CIPHERTEXT Variable
TAG 16 Bytes
Offset Field Type Description
0..3 Magic ASCII Fixed identifier bytes: 0x44 0x4B 0x45 0x4D ('DKEM').
4 Version uint8 Protocol version (current: 0x01).
5 Flags uint8 Reserved for session extensions (default: 0x00).
6..13 Sequence uint64 (BE) Strict monotonic sequence counter for replay defense.
14..25 Nonce Raw Bytes 12-byte cryptographically secure random initialization vector.
26..29 Ciphertext Length uint32 (BE) Explicit byte length of following ciphertext payload.
30..N Ciphertext Raw Bytes Plaintext encrypted with AES-256-GCM.
N..N+16 Authentication Tag Raw Bytes 16-byte GHASH authentication tag verifying header and ciphertext integrity.

Command Line Interface

Standard CLI commands.

The reference terminal frontend (main_chat.py) provides an interactive shell for session establishment, messaging, and teardown.

start --listen <port> Starts as the session initiator, waiting for a peer to connect.
start --connect <host:port> Starts as the joining party, connecting to a waiting peer.
send <message text> Encrypts and transmits an authenticated message in an active session.
status Displays session state and message counters. No key material is displayed.
end Ends the session and zeroizes all key material in memory.
help Lists all available terminal commands and format indicators.
Transparency

Data handling practices.

Direct peer-to-peer communication requires no central servers, no user accounts, and no data harvesting.

Privacy Policy

The engine operates strictly between two endpoints selected by the users. No telemetry, third-party analytics, or crash reports are gathered or transmitted. Keys exist only in volatile RAM and are overwritten upon key rotation and session closure.
